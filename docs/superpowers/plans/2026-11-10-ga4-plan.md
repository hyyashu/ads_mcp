## 2. Shared modules (built in batch 1, used by every tool)

### 2.1 `src/platforms/ga4/report.ts`

**Periods.** Input fields (shared object `periodFields`):
```ts
date_range: z.enum(["TODAY","YESTERDAY","LAST_7_DAYS","LAST_14_DAYS","LAST_28_DAYS","LAST_30_DAYS","LAST_90_DAYS","THIS_MONTH","LAST_MONTH"]).default("LAST_28_DAYS")
start_date: day.optional(), end_date: day.optional()   // day = YYYY-MM-DD + isRealDate; refine datesOk/datesMsg
```
`resolvePeriod(v, tz, now)` → `{ startDate, endDate, label }`, always explicit `YYYY-MM-DD` computed in the property time zone
(`todayIn(tz)`), so the output states the exact days used. LAST_N_DAYS = N complete days ending yesterday (same as GA's
`NdaysAgo`..`yesterday`); THIS_MONTH = 1st..today; LAST_MONTH = whole previous month. Explicit dates: start ≤ end, end ≤
today in the property zone (else `invalid_argument` naming today's date there).
- Time zone source: `ga4.timeZone` (stored at connect). If null, call `ga4.getProperty()` once and use its `timeZone`;
  if still unknown, send the relative form (`28daysAgo`/`yesterday`) so Google evaluates it in the property zone, and report
  `time_zone: null` with a note. After the report, compare `metadata.timeZone` with the zone used; if different (property
  zone changed since connect) add a note "dates were resolved in X but the property now reports in Y".
- Move `todayIn` from `src/platforms/meta/insights.ts` to `src/platforms/core/report-math.ts` and re-export it from insights
  (one-line change to a shared file; tell the foundation builder / reviewer).

**Field validation (generic tools).** `validateFields(ga4, req)`:
1. zod already bounds the shape: names match `/^[A-Za-z][A-Za-z0-9_]{0,99}(:[A-Za-z0-9_\[\]]{1,100})?$/`, ≤ 9 dimensions,
   ≤ 10 metrics (facts 13, 37).
2. `ga4.getMetadata()` at call time (no cache in v1; see open question 4). Build maps apiName → metadata plus
   deprecatedApiNames → apiName.
3. Every dimension, metric, filter field and order field must be known. A deprecated name is replaced by its current name
   and reported in `renamed[]`. An unknown name fails `invalid_argument` with up to 3 suggestions (case-insensitive prefix /
   substring match on apiName and uiName), e.g. `Unknown metric "conversions". Did you mean: keyEvents, sessionKeyEventRate?`.
   GA4 renamed conversions to key events; add a fixed hint for `conversions`, `sessionConversionRate`, `userConversionRate`.
4. A metric with `blockedReasons` fails `platform_permission_denied`: "Your access to cost (or revenue) metrics is blocked
   for this property" (fact 22).
5. Dimension filter fields must be dimensions, metric filter fields metrics; order-by names must be in the request (fact 18).
6. `ga4.checkCompatibility({dimensions, metrics, dimensionFilter, metricFilter})`; any `INCOMPATIBLE` → `invalid_argument`
   listing the incompatible names and saying "these cannot be combined in one GA4 report".

Fixed-shape tools skip steps 1-3 (their names are constants) but run step 6 when they include optional metrics (Google Ads
cost metrics) and drop the incompatible optional ones, reporting `omitted_metrics` with the reason.

**Filters (non-recursive, bounded; no recursive zod for MCP schemas).**
```ts
const dimFilter = z.object({
  field: name,
  match: z.enum(["exact","begins_with","ends_with","contains","full_regexp","partial_regexp","in_list","empty"]),
  value: z.string().max(500).optional(),            // required unless in_list/empty
  values: z.array(z.string().max(500)).min(1).max(50).optional(),   // in_list only
  case_sensitive: z.boolean().default(false),
  negate: z.boolean().default(false),
});
const metricFilter = z.object({
  field: name,
  op: z.enum(["eq","lt","lte","gt","gte","between"]),
  value: z.number().finite(), to_value: z.number().finite().optional(),  // between only
});
dimension_filters: z.array(dimFilter).max(10).optional(), dimension_filter_logic: z.enum(["and","or"]).default("and"),
metric_filters: z.array(metricFilter).max(5).optional()   // always ANDed
```
`toFilterExpression()` maps to fact 14-17 shapes (`negate` → `notExpression`; one filter → `{filter}`; several →
`andGroup`/`orGroup`). Integers go as `{int64Value: String(n)}`, others `{doubleValue}`. A superRefine checks
value/values/to_value presence per match/op.

**Response shaping.** `shapeReport(res, req)` →
```ts
{
  rows: { dimensions: Record<string,string>, metrics: Record<string, number|null> }[],
  metric_headers: { name: string, type: string }[],
  totals: Record<string, number|null> | null,   // from res.totals[0] when TOTAL was requested
  row_count: number,                             // res.rowCount ?? 0
  data_quality: {
    sampled: boolean,
    sampling: { date_range_index: number, samples_read: number, sampling_space_size: number, percent_of_events: number|null }[],
    subject_to_thresholding: boolean,
    other_row: boolean,                           // metadata.dataLossFromOtherRow
    empty_reason: string | null,
    notes: string[],                              // plain-language explanation of each flag that is true
  },
  currency_code: string | null, time_zone: string | null,     // from metadata, else the client's
  quota: { tokens_per_day_remaining, tokens_per_hour_remaining, tokens_per_project_per_hour_remaining: number|null } | null,
}
```
Metric strings are parsed with `Number`; non-finite → `null` (never 0). Notes text:
- sampled: "GA4 sampled this report: based on X% of events for date range N. Figures are estimates."
- thresholding: "GA4 applied thresholding: rows with few users may be withheld (privacy), so totals over rows can be lower
  than the true total."
- other_row: "Some rows were grouped by GA4 into '(other)' because of high cardinality. Values in '(other)' cannot be
  attributed to a specific row."
- quota: when `tokensPerHour.remaining` < 10% of what was consumed + remaining, note "GA4 hourly quota for this property is
  low".
`(not set)` and `(other)` dimension values are passed through unchanged, never dropped.

**Quota errors.** `withGa4Quota(fn)` catches `ToolError` code `quota_exceeded` from the Data API and rethrows with the same
code and retryAfter but a GA4 message: "Google Analytics reporting quota for this property is used up (Standard: 40,000
tokens per hour, 200,000 per day; daily quota resets at midnight Pacific). Try again later or narrow the report." Never retried
by us (http-core does not retry quota errors). Data API requests always set `returnPropertyQuota: true` and tools issue
Data API calls sequentially (concurrency limit 10 per property, fact 33).

**Row caps.** One Data API request per page; `limit` input ≤ `HARD_ROW_CAP` (10,000). Generic tools expose `offset`;
`truncated = offset + returned < row_count`, `next_offset` = offset + returned or null. Fixed tools: `limit` default 50 or
100, max 1,000, `truncated` from `row_count`, totals from GA4's TOTAL aggregation (so totals never sum just the shown page).
A tool that needs every row (get_conversion_events) uses `ga4.reportAll()` which pages by offset and refuses past its cap
with `tooManyRows` (row_cap convention).

## 4. Tools

Common for all: input has `account_id: accountId` (from `ga4/tools/common.ts`). Reads use `ga4Read`, writes `ga4Write`.
Every report output includes `property`, `period {start_date, end_date, label}`, `time_zone`, `currency_code`
(monetary metrics are in this currency), and `data_quality` and `quota` from 2.1. Descriptions say "Fetched live from
Google Analytics" and name the API version when alpha. All text from GA4 (names, paths, queries) is untrusted data:
descriptions say so as the ads tools do.

Errors common to all: `auth_expired` (reconnect), `platform_permission_denied` (no access to the property, or blocked
metrics), `not_found`, `quota_exceeded` (GA4 message, `retryAfterSeconds`), `invalid_argument` (bad names, incompatible
fields, bad dates; Google's 400 message passed through redacted), `transient`.

## 7. Open questions and risks (recommended safe choice first)

1. **Realtime cannot show traffic source.** The design says "active users now by source and page"; the Realtime API has no
   source/medium/campaign or page path dimension (fact 29). *Recommend:* ship by page title / screen (`unifiedScreenName`),
   country, device, event, and say so in the description and every response. Owner to accept the design change.
2. **Change history needs the edit scope.** `searchChangeHistoryEvents` accepts only `analytics.edit` (fact 52), so it
   works only on write connections. *Recommend:* keep it a read tool, refuse clearly on read connections without calling
   Google. Alternative (rejected): ask every GA4 connection for `analytics.edit`, which breaks "ask only for what you need".
3. **v1alpha APIs** (funnel report, attribution settings, audiences). Breaking changes are announced as possible.
   *Recommend:* ship them, label `api_version: "v1alpha"` in output and description, keep their code isolated (one file
   each) and cover them with schema-shape tests so a change fails loudly. Do not build any combined tool on funnels.
   `compare_conversion_tracking` may read attribution settings but must tolerate their absence (treat a 404/400 as
   "unknown settings").
4. **Metadata on every generic report** costs two extra API calls (getMetadata, checkCompatibility; quota cost not
   documented). *Recommend:* no cache in v1 (correct, simple); if quota becomes a problem add a 5-minute in-memory
   per-property cache of getMetadata only (configuration, not analytics data, so the no-storage rule is kept).
5. **Totals scope.** That `totals` cover all rows is from knowledge (fact table, unconfirmed). *Recommend:* use them, label
   them "GA4's totals", verify on the first live run, and record the result.
6. **Audience creation complexity.** The full Audience grammar (sequences, scopes, parameter filters, N-day periods,
   event triggers) is large, alpha and immutable once created. *Recommend:* the reduced event-only shape in 4.18 (include any
   / all of up to 5 events, exclude up to 5 events, duration ≤ 540). Add page-path and event-count conditions only after a
   live test confirms the field names (`pagePath` in audience filters and the `eventCount` parameter filter are not shown on
   the fetched pages).
7. **Key event creation is high impact** because Google Ads may import GA4 key events. *Recommend:* as designed
   (high_impact, two approvers) and the summary names linked Ads accounts and whether the event is actually recorded.
8. **Standard limits** come from a Google Help page, not the API reference, and 360 limits are elsewhere. *Recommend:*
   enforce only for `GOOGLE_ANALYTICS_STANDARD`, otherwise let Google decide and pass its error through.
9. **`list_ga4_properties` shape.** Design says "connected properties"; tools are account-scoped and `list_accounts`
   already lists connected ones. *Recommend:* account-scoped details + data streams + properties visible to the connection
   (4.1). Alternative: `accountScope: "none"` DB listing, which duplicates `list_accounts` and cannot show data streams.
10. **Google Ads customer id format in GA4** (`sessionGoogleAdsCustomerId` with or without hyphens) is not stated.
    *Recommend:* filter with digits only, and when it returns nothing while the unfiltered report has rows, say the filter
    may not match the stored format. Confirm on first live run.
11. **Personal data.** `creatorEmailAddress` (Ads links) is dropped; `userActorEmail` (change history) is kept because
    "who changed it" is the point of that tool and it is the tenant's own staff. Owner to confirm.
12. **Date ranges** are resolved to explicit dates in the stored property time zone. If the property's zone changed since
    connect, the response says so (2.1). The shared `todayIn` move touches `src/platforms/core/report-math.ts` and
    `src/platforms/meta/insights.ts`: coordinate with the foundation builder before editing.
